## Modification notice

As section 5 a of the AGPL asks: Vaultwarphpen modifies Vaultwarden by translating it into PHP. The port
started on 27 October 2026 and follows Vaultwarden commit
[`0f44744ef86a2a7bea615af1c024044ce5736187`](https://github.com/dani-garcia/vaultwarden/commit/0f44744ef86a2a7bea615af1c024044ce5736187)
(release 1.37.4, committed on 25 October 2026), pinned in [`parity/reference.json`](parity/reference.json).
The git history records every change; [`PARITY.md`](PARITY.md) shows what has been ported so far.

## Vaultwarden

- **Project:** <https://github.com/dani-garcia/vaultwarden>, formerly known as bitwarden_rs
- **Authors:** Daniel García and the
  [Vaultwarden contributors](https://github.com/dani-garcia/vaultwarden/graphs/contributors)
- **License:** AGPL-3.0-only, the license of Vaultwarphpen ([`LICENSE.txt`](LICENSE.txt) is the same text)

What Vaultwarphpen takes from it:

- **Its behaviour.** Every route, setting, scheduled job, table, template and static asset is ported from
  the Rust source at the pinned commit. Each item of [`parity/matrix.json`](parity/matrix.json) names
  the source location it comes from, and the code names the Rust handlers and modules it ports.
- **Files copied unchanged** by `php artisan parity:sync`:

  | Vaultwarphpen | Vaultwarden |
  |---|---|
  | `database/vaultwarden/sqlite` | `migrations/sqlite` (the `up.sql` files) |
  | `database/vaultwarden/mysql` | `migrations/mysql` (the `up.sql` files) |
  | `database/vaultwarden/postgresql` | `migrations/postgresql` (the `up.sql` files) |
  | `resources/vaultwarden/templates` | `src/static/templates` (Handlebars templates for mails, the admin panel and the web vault's CSS) |
  | `resources/vaultwarden/static` | `src/static/global_domains.json` |

- **Data derived from it:** `parity/matrix.json` and `PARITY.md` are extracted from its source;
  `parity/schema/*.json` describe the databases Vaultwarden itself creates.
- **The reference for the tests.** The differential tests and the CI scripts in `.github/scripts` run a
  Vaultwarden binary next to Vaultwarphpen and compare the answers. CI builds it from the Vaultwarden
  repository; it is not part of Vaultwarphpen.

## Rocket

- **Project:** <https://rocket.rs>, <https://github.com/rwf2/Rocket>, version 0.5.2 as locked by Vaultwarden
- **License:** MIT or Apache-2.0; Vaultwarphpen uses it under the MIT license, reproduced
  [below](#mit-license-rocket)

Vaultwarden runs on Rocket, so its answers include Rocket's. [`app/Http/DefaultCatcher.php`](app/Http/DefaultCatcher.php)
copies Rocket's default catcher: the HTML error page, the JSON error body and the reason phrase and
description of every status. The rest is behaviour reproduced without copying code: request guards,
catchers per mount point, the order of the response fairings, media type negotiation and the handling
of form and JSON bodies (`app/Http`, `app/Auth`).
