## Modification notice

As section 5 a of the AGPL asks: Vaultwarphpen modifies Vaultwarden by translating it into PHP. The port
started on 27 October 2026 and follows Vaultwarden commit
[`64ae55ceb2e33aa08e7291d50ca010c679064842`](https://github.com/dani-garcia/vaultwarden/commit/64ae55ceb2e33aa08e7291d50ca010c679064842)
(release 1.37.4 and the fixes after it, committed on 28 October 2026), pinned in [`parity/reference.json`](parity/reference.json).
The git history records every change; [`PARITY.md`](PARITY.md) shows what has been ported so far.

## Vaultwarden

- **Project:** <https://github.com/dani-garcia/vaultwarden>, formerly known as bitwarden_rs
- **Authors:** Daniel García and the
  [Vaultwarden contributors](https://github.com/dani-garcia/vaultwarden/graphs/contributors)
- **License:** AGPL-3.0-only, the license of Vaultwarphpen ([`LICENSE.txt`](LICENSE.txt) is the same text)

What Vaultwarphpen takes from it:

- **Its behaviour.** Every route, setting, scheduled job, table, template and static asset is ported from
  the Rust source at the pinned commit. Each item of [`parity/matrix.json`](parity/matrix.json) names
  the source location it comes from, and the code names the Rust handlers and modules it ports.
- **Files copied unchanged** by `php artisan parity:sync`:

  | Vaultwarphpen | Vaultwarden |
  |---|---|
  | `database/vaultwarden/sqlite` | `migrations/sqlite` (the `up.sql` files) |
  | `database/vaultwarden/mysql` | `migrations/mysql` (the `up.sql` files) |
  | `database/vaultwarden/postgresql` | `migrations/postgresql` (the `up.sql` files) |
  | `resources/vaultwarden/templates` | `src/static/templates` (Handlebars templates for mails, the admin panel and the web vault's CSS) |
  | `resources/vaultwarden/static` | `src/static/global_domains.json`, `src/static/images` and `src/static/scripts` (the images of the mails and the web pages, the scripts and styles of the admin panel and the 404 page) |

- **Data derived from it:** `parity/matrix.json` and `PARITY.md` are extracted from its source;
  `parity/schema/*.json` describe the databases Vaultwarden itself creates.
- **The reference for the tests.** The differential tests and the CI scripts in `.github/scripts` run a
  Vaultwarden binary next to Vaultwarphpen and compare the answers. CI builds it from the Vaultwarden
  repository; it is not part of Vaultwarphpen.
- **The way its own end-to-end tests drive the web vault.** `tests/Clients` follows Vaultwarden's
  Playwright tests (`playwright/` at the pinned commit) in how it finds its way through the web vault.

## Web vault

The release archives (built by `php artisan release:build` and attached to the
[releases](https://github.com/christianrudde/vaultwarphpen/releases)) include, unchanged, the web vault that
`parity/reference.json` pins, in `web-vault/`: Vaultwarden's build of the Bitwarden web client, version
2026.8.0. It is licensed under the GPL-3.0, whose text is in [`LICENSES/GPL-3.0.txt`](LICENSES/GPL-3.0.txt).
The libraries bundled into its scripts keep their notices in the `*.LICENSE.txt` files next to them. The
web vault is a separate program that the browser runs; the archives only bring it along with Vaultwarphpen.

Its Corresponding Source, as section 6 of the GPL-3.0 calls it, is at these tags, which
`web_vault_source` in `parity/reference.json` pins:

- the source of the web client: <https://github.com/vaultwarden/vw_web_builds/tree/v2026.8.0+0>,
  Vaultwarden's fork of [bitwarden/clients](https://github.com/bitwarden/clients) (tag `web-v2026.8.0`)
  with its changes for Vaultwarden
- the scripts that build it with `npm run dist:oss:selfhost`, which leaves out the code under the
  Bitwarden License: <https://github.com/dani-garcia/bw_web_builds/tree/v2026.8.0>

So that the source stays available with the archives, whatever happens to those repositories, every
release carries GitHub's archives of both tags next to its own: `web-vault-<version>-source-vw_web_builds.tar.gz`
and `web-vault-<version>-source-bw_web_builds.tar.gz`. The libraries the web client is built with come
from npm in the versions its `package-lock.json` names.

The archives take the build from the image `ghcr.io/dani-garcia/bw_web_builds` (also
`docker.io/vaultwarden/web-vault`) with the digest that `parity/reference.json` pins, as `php artisan
vaultwarden:web-vault` does. The image names no source of its own; the tags above are the ones
bw_web_builds published with that build.

## Rocket

- **Project:** <https://rocket.rs>, <https://github.com/rwf2/Rocket>, version 0.5.2 as locked by Vaultwarden
- **License:** MIT or Apache-2.0; Vaultwarphpen uses it under the MIT license, reproduced
  [below](#mit-license-rocket)

Vaultwarden runs on Rocket, so its answers include Rocket's. [`app/Http/DefaultCatcher.php`](app/Http/DefaultCatcher.php)
copies Rocket's default catcher: the HTML error page, the JSON error body and the reason phrase and
description of every status. [`app/Support/WebVault.php`](app/Support/WebVault.php) copies its table
of known file extensions and their media types. The rest is behaviour reproduced without copying code:
request guards, catchers per mount point, the order of the response fairings, media type negotiation,
the rules for path segments and the handling of form and JSON bodies (`app/Http`, `app/Auth`).
